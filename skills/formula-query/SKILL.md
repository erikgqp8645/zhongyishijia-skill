# formula-query

## 核心能力

给定方剂名，返回 **结构化 Markdown 报告**。两种输出模式：

| 模式 | 命令 | 何时用 |
|------|------|--------|
| **简表**（默认） | `python scripts/formula_query.py <方剂名>` | 快速浏览、管道后续处理 |
| **完整报告** | `python scripts/formula_query.py <方剂名> --full-report [-o file.md]` | 学习、整理、归档 |

默认输出简表（兼容远端 v2.1），加 `--full-report` 进入完整报告模式（13 章节终极版）。

## 工具

```bash
# 简表模式（默认）
python scripts/formula_query.py <方剂名>
python scripts/formula_query.py <方剂名> --max-cards 20

# 完整报告（13 章节模板）
python scripts/formula_query.py <方剂名> --full-report
python scripts/formula_query.py 小柴胡汤 --full-report -o 小柴胡汤.md
```

## 输入

- 方剂名（必填）：如 `桂枝人参汤`、`小柴胡汤`、`甘草泻心汤`、`麻黄汤`

## 输出：完整报告模式（13 章节）

报告模板位于 `templates/formula_report_template.md`，由 `formula_query.py` 渲染。所有章节都从 `evidence_cards.jsonl` 自动提取——**不是硬编码**。

```
一、出处溯源
  ├── 1.1 经典原文（按朝代列出最早 8 条主卡片，过滤朝代误标）
  ├── 1.2 组成（药物、剂量、炮制表）
  └── 1.3 煎服法（独立提取）

二~九、历代医家注解（按朝代分组，按书分组）
  ├── 东汉 / 晋 / 南北朝 / 唐 / 宋 / 金 / 元 / 明 / 清 / 民国 / 现代
  └── 缺数据朝代自动跳过

十、病机归纳
  ├── 10.1 核心病机（一句话概括，从东汉《伤寒》《金匮》clinical_theory 抽）
  ├── 10.2 病因病机表（病机关键词抽取）
  ├── 10.3 证候要点表（症状-病机映射）
  └── 10.4 治法方解（君臣佐使 / 配伍 / 方解）
```

## 主/次卡片分类（--full-report 专用）

为了让报告"只讲本方、不混入他方"，脚本对所有匹配的卡片做两层过滤：

| 类型 | 判定 | 用途 |
|------|------|------|
| **主卡片（primary）** | `keyword in card['title']` | 所有 13 章节的数据源 |
| **次卡片（secondary）** | 仅正文提及 keyword | 不进报告；只在 stderr 提示数量 |

为什么必须这样？搜索"小柴胡汤"会返回 1274 条，但 title 包含"小柴胡汤"的只有 146 条——剩下 1128 条要么是顺带提及，要么是"加减小柴胡汤""柴胡桂枝干姜汤"等家族方剂。直接渲染所有匹配会把这些他方资料混入主方报告，造成误导。

**加减方二次过滤**：在剂量换算章节，额外排除 title 包含"加减""加味""变方"的卡片，以及 summary 前 20 字含这些词的卡片，确保拿到原方而非变方。

## Fallback 规则

| 触发条件 | 修复动作 |
|---------|---------|
| `formula_query.py` 主卡片为空 | stderr 提示"仅 N 条间接提及"，stdout 打印"请尝试更精确的关键词" |
| 简表模式无任何结果 | stdout 提示用 `scripts/text_search.py <方剂名>` 全文检索 |
| SQLite 文件找不到 | 提示用户检查 `--references-dir` 参数 |
| 某章节数据不足（如剂量换算无汉制原方） | 显示说明性提示"数据库中未保留汉制原方剂量" |

## 边界

- 只返回有历史文献依据的条文，不做方剂现代配伍解读
- 不在无 SOURCE_MAP 命中时编造朝代/作者（返回"待考"时须标注）
- 病机归纳、临床应用等章节为数据自动提取，非人工辨证——需标注"仅供参考"
- 简表模式（无 `--full-report`）= 远端 v2.1 默认行为，向后兼容

## 关键坑

1. **朝代误标过滤**：标题含"重订通俗伤寒论"等后世整理本的卡片，`identify_source()` 可能错判为东汉。`generate_classic_origins()` 内置过滤：东汉标签 + source_ref/book 包含"重订/补订/新编/校注/白话/通俗"时直接跳过。
2. **正则要支持炮制在剂量前**：处方格式是"柴胡（去苗）半斤"或"半夏（洗）9克"，正则是 `r'([\u4e00-\u9fff]+)(?:（[^）]*）)?\s*([\d.]+)(克|两|...)?'`——**药名只用纯中文字符**，否则会吞掉剂量前的数字。
3. **表格渲染不要重复表头**：模板里已经写了 `| 列1 | 列2 |\n|:----:|:----:|`，生成函数只返回数据行，不返回完整表。
4. **数据回退策略**：汉制原方（两/铢）在数据库中已大半被蒸馏为"现代克数"，《伤寒论》原方"柴胡半斤"在 evidence_cards.jsonl 里也是"柴胡12克"。这是蒸馏脚本的设计，不是 bug。脚本会优雅降级：找不到汉制剂量时显示提示，并展示"现代剂量（带原始数据来源）"。
5. **表格头重复 bug**：`generate_*_table()` 必须只返回数据行。如果返回含表头的整表，模板渲染后会出现两个表头。早期版本有这个 bug，已修复。
